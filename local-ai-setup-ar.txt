================================================================================
أولاً: الحقيقة الصريحة
================================================================================

مشكلتك ليست النموذج — مشكلتك معمارية التنفيذ.

لا Claude Opus ولا أي agent آخر ينفّذ مشروعاً من الصفر بـ prompt واحد طوال الليل،
والسبب أن الـ context يمتلئ والأخطاء تتراكم من غير بوابة تحقق.

الـ agents التي تعمل فعلاً لساعات تعمل هكذا:

    قائمة مهام صغيرة
        + حلقة تنفيذ
        + اختبار بعد كل مهمة
        + commit عند النجاح
        + rollback عند الفشل

النموذج المحلي ينفع تماماً لهذا الدور، لكن ضمن هذه المعمارية وليس بدونها.

================================================================================

  المكوّن                            |  الواقع
  -----------------------------------|--------------------------------------
  Quadro T2000                       |  4GB VRAM فقط — غير كافٍ لأي نموذج

الخلاصة:

الحل الوحيد المنطقي: نموذج MoE بـ ~3B active parameters.
أي أنه بحجم 30B لكنه يقرأ 3B فقط لكل token
    ← سرعة فئة 7B مع ذكاء فئة 30B.


================================================================================
ثالثاً: النموذج — خياران فقط
================================================================================

الخيار 1) gpt-oss-20b   ← ابدأ من هنا
--------------------------------------
  - الحجم: ~12GB بصيغة MXFP4
  - Active parameters: 3.6B
  - Tool calling أصلي وقوي (وهذا أهم شيء لأي agent)
  - Context: 128k
  - يترك لك مساحة RAM مريحة
  - السرعة المتوقعة على جهازك: 10 - 14 tok/s

الخيار 2) Qwen3-Coder-30B-A3B-Instruct
--------------------------------------
  - الحجم: ~18.6GB بصيغة Q4_K_M
  - Active parameters: 3.3B
  - أقوى في تحرير الكود وصيغة الـ diff
  - ثقيل على 32GB مع الـ KV cache
  - السرعة المتوقعة: 8 - 12 tok/s
    (تقارير المستخدمين تذكر 12-15 tok/s على DDR4 مع 32GB)
  - يوجد نسخة أحدث اسمها Qwen3.6-35B-A3B تستحق التجربة

تحذير:
انسَ Qwen3-Coder-Next 80B-A3B — حتى بـ Q4 يحتاج حوالي 45GB.


================================================================================
رابعاً: المحرّك — استبدل Ollama بـ llama.cpp
================================================================================

Ollama يسهّل الأمور لكنه يأخذ منك التحكم الذي تحتاجه هنا.

المفتاح هو flag اسمه n-cpu-moe:
يُبقي الخبراء (experts) على الـ CPU، ويُبقي الـ attention والـ KV cache
والـ router على الـ GPU. هكذا تستغل الـ 4GB في الجزء الذي يستفيد منها فعلاً.

الأمر (اتجاه LTR):
--------------------------------------------------------------------------------
llama-server -m gpt-oss-20b-mxfp4.gguf \
  --n-cpu-moe 20 \
  -ngl 99 \
  -c 65536 \
  --cache-type-k q8_0 --cache-type-v q8_0 \
  -t 8 \
  --jinja \
  --host 127.0.0.1 --port 8080
--------------------------------------------------------------------------------

شرح الخيارات:

  --n-cpu-moe 20        ابدأ بـ 20 وانزل رقماً رقماً حتى تصل إلى OOM على
                        الـ GPU. الرقم الأقل = أسرع.

  -t 8                  ثمانية threads فيزيائية (وليس 16).
                        الـ hyperthreading يضر هنا.

  --cache-type-k/v      q8_0 يُنزّل ذاكرة الـ KV إلى النصف.
                        ضروري عند context بحجم 64k.

  --jinja               إلزامي كي يعمل tool calling بشكل صحيح.


إذا أردت البقاء على Ollama:
---------------------------
الشيء الإجباري هو رفع الـ context. القيمة الافتراضية 4096 وهذه تكسر
الـ tool calling بصمت وبدون أي رسالة خطأ.

الأوامر في PowerShell (اتجاه LTR):
--------------------------------------------------------------------------------
$env:OLLAMA_FLASH_ATTENTION = "1"
$env:OLLAMA_KV_CACHE_TYPE   = "q8_0"
$env:OLLAMA_KEEP_ALIVE      = "-1"     # لا يُنزّل النموذج من الرام طوال الليل
$env:OLLAMA_CONTEXT_LENGTH  = "65536"
--------------------------------------------------------------------------------

================================================================================
سادساً: الحلقة الليلية — هذا هو الجواب الفعلي على سؤالك
================================================================================

هذا السكربت هو ما يجعل النموذج يعمل 8 ساعات لوحده.

الفكرة:
    مهمة واحدة صغيرة لكل استدعاء
    + context نظيف في كل مرة
    + اختبار يقرر هل نكمل أم نرجع

ملف night-run.ps1 (اتجاه LTR):
--------------------------------------------------------------------------------
# night-run.ps1
$ErrorActionPreference = "Continue"
$Root = "D:\work\my-project"
$Log  = "$Root\.agent\night-$(Get-Date -f yyyyMMdd-HHmm).log"
$MaxRetries = 2
Set-Location $Root

while ($true) {
    $line = Select-String -Path "$Root\TASKS.md" -Pattern '^\s*-\s*\[ \]\s+(.+)$' |
            Select-Object -First 1
    if (-not $line) { "== ALL TASKS DONE ==" | Tee-Object -Append $Log; break }

    $task = $line.Matches[0].Groups[1].Value
    "=== [$(Get-Date -f HH:mm)] TASK: $task" | Tee-Object -Append $Log

    $base = (git rev-parse HEAD)
    $ok = $false

    for ($i = 1; $i -le $MaxRetries; $i++) {
        $prompt = @"
اقرا RULES.md و ARCHITECTURE.md اولا والتزم بهما حرفيا.
نفذ هذه المهمة فقط ولا شيء غيرها:
$task
بعد التنفيذ شغل الاختبارات وتاكد انها تنجح.
لا تعدل اي ملف خارج نطاق المهمة.
"@
        opencode run $prompt 2>&1 | Tee-Object -Append $Log

        npm test 2>&1 | Tee-Object -Append $Log   # بدّلها: php artisan test / flutter test
        if ($LASTEXITCODE -eq 0) { $ok = $true; break }
        "-- retry $i : failed" | Tee-Object -Append $Log
    }

    if ($ok) {
        git add -A
        git commit -m "feat: $task" | Out-Null
        (Get-Content "$Root\TASKS.md") -replace [regex]::Escape("- [ ] $task"), "- [x] $task" |
            Set-Content "$Root\TASKS.md" -Encoding utf8
        "++ PASSED" | Tee-Object -Append $Log
    } else {
        git reset --hard $base | Out-Null
        (Get-Content "$Root\TASKS.md") -replace [regex]::Escape("- [ ] $task"), "- [!] $task (BLOCKED)" |
            Set-Content "$Root\TASKS.md" -Encoding utf8
        "!! BLOCKED - moving on" | Tee-Object -Append $Log
    }
}
--------------------------------------------------------------------------------

ملاحظة على السكربت:
السطر `@"` ... `"@` هو here-string في PowerShell. علامة الإغلاق `"@` يجب أن
تكون في بداية السطر تماماً بدون أي مسافة قبلها، وإلا سيفشل السكربت.

في الصباح:
  - تفتح TASKS.md وترى ما انتهى وما وُضعت عليه علامة [!]
  - git log يعطيك commit لكل مهمة ناجحة، فالرجوع سهل

مهم جداً قبل التشغيل:
--------------------------------------------------------------------------------
powercfg /change standby-timeout-ac 0
--------------------------------------------------------------------------------
وإلا اللابتوب سينام بعد ساعة وتضيع الليلة.

project/
|-- RULES.md          # 150 سطر كحد أقصى. قواعد إلزامية + مثال صح/غلط لكل قاعدة

  خطأ  : "استخدم أسماء واضحة"
